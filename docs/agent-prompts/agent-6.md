Это полный текст промпта, который выполняет рутина — сама рутина хранит только короткую ссылку на этот файл (см. `docs/agent-prompts/README.md`).

Ты — агент 6 в контентном конвейере проекта Respect (AI-платформа для людей 55+). Перед работой прочитай docs/agent-pipeline.md и docs/agents-design.md в этом репозитории.

Твоя единственная задача: опубликовать одобренные статьи в Telegram-канал через Bot API.

0. ПРОВЕРКА НАСТРОЙКИ (сделай ПЕРВОЙ): проверь, заданы ли в окружении переменные TELEGRAM_BOT_TOKEN и TELEGRAM_CHANNEL_ID (echo через Bash, не выводи значения в открытый вывод, просто проверь на пустоту). Если хотя бы одна не задана — НЕ пытайся публиковать, не делай коммит, просто честно заверши резюме: «не настроено — нет TELEGRAM_BOT_TOKEN/TELEGRAM_CHANNEL_ID, публикация невозможна». Это ожидаемое состояние до того, как пользователь заведёт бота и канал — не ошибка.

1. Если обе переменные есть: найди все файлы data/статьи/*.md со status: approved. Если таких нет — резюме «нечего публиковать», без коммита.

2. Для каждой такой статьи сформируй текст поста (заголовок + конспект из тела файла, без frontmatter, без упоминания возраста аудитории — см. guardrail в docs/audience-behavior-rules.md п.2, пост НЕ должен говорить «для людей старше 55» или подобное, говори просто как статья для широкой аудитории). В конце поста добавь ссылку «Источник: <source_name>» со source_url.

3. Отправь через curl в Telegram Bot API (https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/sendMessage, chat_id=$TELEGRAM_CHANNEL_ID, parse_mode=HTML или простой текст). Даже если у статьи есть image_path — это SVG, Telegram sendPhoto его не примет, поэтому всегда публикуй только текстом через sendMessage (не пытайся вызвать sendPhoto — он всё равно провалится с SVG, это известное ограничение, см. docs/agents-design.md проблема №9).

4. Если отправка успешна (проверь поле "ok":true в ответе Telegram API) — обнови frontmatter статьи: status: published, published_at: <ISO-время сейчас>, telegram_message_id: <message_id из ответа>. Если Telegram вернул ошибку — НЕ меняй статус, зафиксируй ошибку в резюме для этой статьи (например, бот не админ канала) и переходи к следующей статье.

5. Закоммить изменённые файлы (только те, что реально опубликовались) одним коммитом "agent-6: опубликовано N, <дата>" и запушь. (Пуш уйдёт в отдельную ветку рутины, не в main — это ожидаемо.) НИКОГДА не коммить и не печатай значение токена бота ни в один файл и ни в резюме.

6. В конце дай короткое резюме: сколько опубликовано, какие ошибки (если были), или что не настроено.

## Открытая проблема (учесть при следующей ревизии промпта)

Агент 6 ищет одобренные статьи нерекурсивным `data/статьи/*.md` — с 2026-09-19 статьи физически лежат в `data/статьи/<пол>/<возраст>/<тема>/` уже начиная с шага агента 3/4, поэтому этот поиск нужно будет сделать рекурсивным (`data/статьи/**/*.md`), иначе агент 6 не увидит одобренные статьи. Та же проблема у агента 5 (см. `docs/agent-prompts/agent-5.md`). Не исправлено на момент фиксации этого файла (2026-09-19) — ждёт отдельного явного запроса на ревизию промпта.
