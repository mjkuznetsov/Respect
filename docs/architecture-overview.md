# Respect — обзор архитектуры (единая точка входа для ИИ и людей)

Дата: 2026-09-19. Назначение этого файла: если с текущей сессией ассистента (Claude) или с доступом к облачной инфраструктуре Anthropic что-то случится, **любой ИИ-агент или человек должен суметь восстановить полную картину системы, прочитав только этот репозиторий**, начиная с этого файла. Это не замена остальным `docs/*`, а карта — что где лежит и как связано, плюс самое актуальное состояние на дату выше.

**Правило поддержания этого файла и всей папки `docs/`:** любое изменение архитектуры, роли агента или промпта должно быть закоммичено и запушено в этот репозиторий в тот же день — минимум раз в сутки синхронизация накопленных изменений. GitHub — единственное постоянное хранилище состояния конвейера; сами облачные рутины (см. ниже) ничего не помнят между запусками, и текущая сессия ассистента может прерваться в любой момент.

## Что такое Respect

AI-платформа для людей 40+ (не 55+ — граница пересмотрена, см. «Известные несостыковки» ниже). Первый практический шаг к продукту — не сам продукт, а **контентный конвейер для Telegram-канала**: параллельно (1) собирать аудиторию через полезный контент и (2) копить данные о том, что этой аудитории откликается. Продуктовый контекст и мотивация — `docs/insights.md`.

## Как устроены «агенты» — важно понять это первым

Каждый агент 1–7 (и рецензенты/редакторы, см. ниже) — это не часть одного долгоживущего чата с ассистентом, а **отдельная облачная рутина (CCR, Claude Code cloud routine)**: запись в системе `RemoteTrigger` с cron-расписанием (в UTC), которая по расписанию поднимает **новую, изолированную сессию Claude без памяти о предыдущих запусках**, дающую ей репозиторий (git clone), доступные инструменты и, для агентов 6/7, доступ к секретам через привязанное облачное окружение (`environment`). Сессия делает свою работу, коммитит в свою ветку, пушит и исчезает.

Следствия:
- **Единственная память конвейера — этот git-репозиторий.** Агент N+1 узнаёт, что сделал агент N, только читая файлы, которые агент N закоммитил и запушил (и которые слил в `main` человек).
- **Промпт каждого агента — это то, что реально выполняется тем самым `RemoteTrigger`, а не текст в этом файле сам по себе.** Тексты синхронизированы (см. ниже, `docs/agent-prompts/`), но источник правды при расхождении — сама рутина (`RemoteTrigger action:"get"`, нужен доступ к API Anthropic, которого у стороннего ИИ, читающего только этот репозиторий, может не быть).
- Никакой отдельной БД/сервера нет сознательно — файлы + git вместо этого (человекочитаемо, диффится, не требует инфраструктуры).

## ✅ Нестыковка агент 3 vs возрастная редактура — решена 2026-09-19

Было: агент 3 (раскладка по папкам) и связка рецензент→редактор независимо конкурировали за одни и те же `status: collected` статьи в корне `data/статьи/`, оба около 9:00 UTC — это уже осиротило 6 статей (см. `git log` за 2026-09-19), пришлось вручную возвращать их в `collected`.

Стало: очерёдность в конвейере теперь строго `1 → 2 → 3 → 4 → [рецензент] → [редактор] → 5 → 6 → 7`. Рецензенты/редакторы читают только `status: approved` (выход агента 4), рекурсивно по всем подпапкам, и не меняют `status`, поэтому больше не конкурируют с агентом 3 (который работает только с `collected` в корне) и не создают тупиковых состояний для агента 4 (который работает только с `sorted`). Расписание разведено с запасом: агент 4 (10:00) → рецензенты (10:15) → редакторы (10:30) → агент 5 (11:00). Подробности решения — `docs/agents-design.md`, проблема №13.

## Модель данных

### `data/статьи/<id>.md` — одна статья

Frontmatter (YAML) + тело (конспект/текст на русском). Ключевые поля:

```yaml
id: <slug, = имя файла без .md>
source_url: <URL первоисточника>
source_name: <название источника>
title: "<заголовок>"
gender: мужчины | женщины | все
age_range: 40-49 | 50-59 | 60-69 | 70-79 | 80+ | все
topic: здоровье | долголетие | психология | спорт | досуг | работа | финансы | технологии | юридическая защита | обучение
status: collected → sorted → approved/rejected → published
collected_date / sorted_date / selected_date / edited_date / checked_date / published_at: <даты>
editor / editor_notes: <если прошла через возрастную редактуру>
rejection_reason: <если rejected>
image_path: data/статьи/images/<id>.svg
telegram_message_id: <после публикации>
```

**Расположение на диске меняется по ходу конвейера:**
- `collected` (после агента 2) — всегда в корне `data/статьи/<id>.md`.
- `sorted` (после агента 3) — перенесена в `data/статьи/<пол>/<возраст>/<тема>/<id>.md`.
- `selected` (после связки рецензент→редактор) — **остаётся в корне**, путь не меняется (см. критическую нестыковку выше).
- `approved`/`rejected`/`published` — путь не меняется относительно того, где статья была на момент вердикта агента 4 (то есть физически может быть и в подпапке, и в корне — зависит от того, каким путём статья туда попала).

### Другие данные
- `data/источники.xlsx` — источники (агент 1 пишет, агент 2 только читает, колонку «Подтверждение» проставляет человек).
- `data/queries_log.md` — журнал поисковых запросов агента 1 (дедуп формулировок).
- `data/рецензии/<id>-<когорта>.md` — вердикты возрастных рецензентов.
- `data/подборки/<дата>.md` — **устарело**: создавал старый агент 3 (роль отбора 5 статей), новый агент 3 этот файл не создаёт.
- `data/аналитика/<дата>.md` — ежедневный снимок метрик от агента 7.
- `data/статьи/images/<id>.svg` — иллюстрации от агента 5.

## Инфраструктура и секреты

- Git: `https://github.com/mjkuznetsov/Respect`, ветка по умолчанию `main`. Каждая рутина работает в своей ветке (`agent-N/<дата>` для 1–4, `claude/<...>` для остальных) и пушит только туда — слияние в `main` делает владелец (или ассистент по явной просьбе), это единственная точка ручного контроля в конвейере.
- Два облачных окружения (`environment`) в Anthropic CCR:
  - **Default** (`env_01BDyCAoWgHK2nfGkb2Fg6hq`) — агенты 1–4, рецензенты/редакторы. Без секретов.
  - **respect-telegram** (`env_01KpNj3TpysMby4SW3VVDsMT`) — агенты 6 и 7 отдельно, потому что в общем «Default»-окружении переменные окружения видны всем рутинам этого окружения, а `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHANNEL_ID` не должны быть доступны агентам 1–5.
- Telegram-канал: `@respect_age`. Публикация текстом (`sendMessage`), не фото — картинки пока SVG, Telegram их не принимает (проблема №9).
- MCP-коннекторы, используемые агентами: `Claude_Docs`/`Claude-Docs` (доступ к докам), `Claude_Code_Remote`, `Firecrawl` (только агент 2, обход egress-блокировки WebFetch), `visualize` (только агент 1, не задействован по назначению).

## Если ты — другой ИИ и читаешь это впервые

1. Не доверяй промптам агентов 1–7/40–81 в этом репозитории вслепую как «истине в последней инстанции» — это snapshot на дату вверху файла; если нужен гарантированно актуальный текст, запрашивай саму рутину через `RemoteTrigger action:"get"` (если есть доступ к API).
2. Прежде чем менять роль/промпт любого агента — прочитай пронумерованный список проблем в конце `docs/agents-design.md` целиком, включая уже решённые (например, №13 — история конфликта агента 3 и возрастной редактуры показывает, как легко два независимых механизма могут случайно начать конкурировать за один и тот же пул статей).
3. После любого изменения архитектуры/промпта: обнови соответствующий файл в `docs/agent-prompts/`, обнови `RemoteTrigger` (`action:"update"`) на реальной рутине (не только файл в репозитории — иначе они разойдутся), закоммить и запушить в `main` в тот же день.
4. Никогда не клади секреты (Telegram-токен и т.п.) в файлы, коммиты или ответы — они живут только в переменных окружения `environment` `respect-telegram`.
